Automating video posts

The export decodes the source into raw frames and redraws every one of them from the exact render state the preview last used, so the file that downloads cannot drift from what was on screen. WebCodecs for encode and decode, mediabunny for MP4 muxing. Frames move through a bounded queue with backpressure, and a watchdog fails a silently stalled decoder instead of hanging forever, because a decoder that stops reports nothing. The queue behind it is driven from a Google Sheet, so a non-engineer can fill the pipeline. It is the largest part of the codebase by a wide margin, 93 files and around 17,900 lines.

Automating carousel posts

Slides render headlessly through the real editor canvas rather than a reimplementation of it, which is what keeps an automated post identical to a hand-made one. Slide data is injected before the page loads, so the renderer takes no auth and reads nothing from the database. It waits until every font and image is genuinely resident before it draws, so a slide cannot go out in the wrong typeface, and it emits a 1080x1350 PNG at full fidelity.

FeedForce

technical co-founder, now

Sonotool is where FeedForce started. Having built the thing once for ourselves, the obvious next question was what it looks like generalised for other people, and that is what FeedForce is: an AI workspace for social content, which I'm building as its technical co-founder.

A brand signs up with its Instagram. An agent in that user's own sandbox studies the feed and builds the brand's post templates, then drafts posts in them for the team to edit and publish. The agent works as that user, so the database's access rules still apply, and model and research API keys never enter the sandbox: its firewall adds them on the way out. Each user gets one agent turn at a time, held by a lease in Postgres, because two overlapping turns overwrote each other's work on the first real run. Before a build reaches anyone, plain code checks it and a separate reviewer that cannot change anything has to pass it. Chart code the agent writes runs in a sealed worker with no network.

wallet-ledger

Java, concurrency

One account balance, kept correct four ways. Two requests that touch the same account at the same time can overwrite each other, and a test here proves it: 480 concurrent transfers through the unguarded version change the total in every run.

The other three fix it at different prices. A single lock serialises everything. Optimistic locking retries on conflict and, under heavy contention, finished 326 to 345 of 480 transfers after more than 1,600 retries. Row locks ordered by account id finished all 480 with no retries, and the suite shows the deadlock they cause without that ordering. Money moves once per idempotency key, claimed in Redis. Spring Boot, Postgres and Redis, tested against real instances: 69 tests.
